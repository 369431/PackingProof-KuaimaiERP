# PackingProof 快麦 ERP 开发与适配说明

> 本文档适用于 `payload/` 目录内的适配器源码。仓库根目录为 PackingProof 扩展项目结构（`manifest.json`、`submission.json`、`payload/`），见仓库 README。

## 1. 目标与边界

本适配器负责在 PackingProof Desktop 和快麦 ERP 之间转换受限的结构化数据：PackingProof 发布扫码任务，适配器调用快麦开放 API 查询订单，再通过扩展 API v1 提交结果。

适配器不得直接访问 PackingProof 的 SQLite 数据库、配置文件、录像目录或 NAS 凭据，也不得把快麦业务逻辑写入录像和存储核心。快麦 API 凭据只保存在适配器本机的 `.env` 中。

## 2. 最小配置

开发者只需准备快麦开放平台的 App Key、App Secret 和 Session/AccessToken，并填写 `.env`：

| 配置项 | 必填 | 说明 |
| --- | --- | --- |
| `PACKINGPROOF_URL` | 否 | 默认 `http://127.0.0.1:5280` |
| `ERP_PROVIDER` | 否 | ERP 提供方，默认 `kuaimai`，新增提供方见 `src/providers/order-provider.js` |
| `PACKINGPROOF_EXTENSION_INSTANCE_ID` | 否 | 固定扩展实例 ID（测试或工位绑定场景） |
| `KUAIMAI_APP_KEY` | 是 | 快麦应用 App Key |
| `KUAIMAI_APP_SECRET` | 是 | 快麦应用 App Secret |
| `KUAIMAI_SESSION` | 是 | Session 或 AccessToken |
| `KUAIMAI_REFRESH_TOKEN` | 否 | 预留刷新令牌 |
| `KUAIMAI_GATEWAY` | 否 | 默认 `https://gw.superboss.cc/router` |
| `KUAIMAI_SIGN_METHOD` | 否 | `md5`、`hmac` 或 `hmac-sha256` |

适配器使用 `erp.trade.list.query`，以 `outSids` 传入当前快递单号。

## 3. PackingProof 扩展协议

首次启动时适配器申请：

- 权限：`scan-tasks.read`、`scan-results.write`
- 能力：`order.lookup`、`refund.lookup`

主机批准后，扩展凭据保存在被忽略的 `.state.json` 中。适配器长轮询领取扫码任务，先确认任务，再提交带 `deliveryId`、`taskId`、`resultId` 和 `revision` 的结果。

结果状态必须准确区分：

| 场景 | 提交状态 |
| --- | --- |
| 找到订单 | `found` |
| 快麦明确返回空订单列表 | `not_found` |
| Session 或授权失效 | `provider_auth_required` |
| 请求超时 | `timeout` |
| 被限流 | `rate_limited` |
| 其他临时错误 | `unavailable` |

只有 `not_found` 才能触发“此单号不在系统中，请核实再发”。禁止把网络错误、超时或鉴权失败当作查无订单。

## 4. 商品字段映射

商品显示优先级：

1. `outerSkuId`
2. `sysOuterId`
3. `outer_sku_id`
4. `sku`
5. 只有商家编码全部为空时，才回退 `title`、`product_name`、`item_title` 或 `name`

回传时同时填写 `name`、`sku` 和 `merchantSku`。其中 `name` 优先使用商家编码，避免在摄像头浮层显示冗长商品标题。

多 SKU 必须保留为独立商品数组。PackingProof 合并后应使用真实换行显示：

```text
商品：9678-橘色M
9678-燕麦色M
9678-黑色M
9678-绿色M
```

单件 SKU 不附加 `×1`；同一 SKU 数量大于 1 时可以显示 `×N`。`totalItemCount` 必须是过滤后的商品数量总和，桌面端用它显示大号件数并播报“订单 N 件”。

## 5. 退款状态映射

适配器向 PackingProof 提交稳定状态值，桌面端再显示中文：

| 快麦常见状态 | 扩展状态 | 中文显示 |
| --- | --- | --- |
| `WAIT_SELLER_AGREE`、`REQUESTED` | `requested` | 申请中 |
| `WAIT_BUYER_RETURN_GOODS`、`WAIT_SELLER_CONFIRM_GOODS`、`PROCESSING` | `processing` | 处理中 |
| `SUCCESS`、`REFUNDED` | `refunded` | 已退款 |
| `RETURNED` | `returned` | 已退货 |
| `CLOSED`、`REJECTED` | `rejected` | 已拒绝 |
| 无退款标记 | `none` | 无退款 |

退款订单优先播报“订单已退款”，不再继续播报普通件数，避免仓库人员误发。

## 6. 延迟结果与录像状态

快麦查询是异步结果，可能在扫码后的数秒才返回。桌面端实现应满足：

- 以扫码任务绑定的单号、工位和录像会话校验结果
- 当前录像已经停止时，仍处理合法且未过期的结果
- 结果到达时更新当前订单浮层和订单缓存
- 浮层支持拖动，并在窗口缩放后自动保持在摄像头可视区域内
- 对同一订单结果的语音进行短时间去重，避免重复播报

## 7. 查无订单播报

当所有参与 `order.lookup` 的订单来源都明确返回 `not_found`，且单号仍与当前扫码/录制单号一致时，桌面端应：

1. 清除过期的订单商品浮层
2. 显示“单号不在系统中，请核实再发”
3. 播报“此单号不在系统中，请核实再发”
4. 对同一单号进行短时间去重

退款查询返回空结果不能单独触发查无订单播报。

## 8. 验收清单

- `outerSkuId` 和 `sysOuterId` 存在时不显示长标题
- 四个不同 SKU 在浮层中显示四行，第一行只出现一次“商品：”
- 单件商品不显示 `×1`
- 四件订单显示大号 `4`，并播报“订单 4 件”
- 五种退款状态均映射为正确中文，退款单播报“订单已退款”
- 快麦空列表播报“此单号不在系统中，请核实再发”
- 超时、断网、限流、Session 过期均不播报“单号不在系统中”
- 查询稍晚返回以及录像停止后的合法结果仍能显示
- 缩小主窗口后浮层仍在摄像头区域内可见
- `.env`、`.state.json`、密钥和令牌不出现在 Git 历史及日志中
